**Note on the S23 report's F4 wording:** the S23 report said "the outer `<section id="mcentre-nav">` has no aria-label." The live DOM shows the outer section DOES carry `aria-label="ناوبری بخش‌های صفحه"` (from `sectionHtml` + the `MC_SECTION_ORDER` label). The REAL issue is the double-landmark (two labeled landmarks with the same name), not a missing label. The fix is the same (consolidate to ONE landmark), but the diagnosis is corrected here for the record.

### The architectural constraint on F4 (the load-bearing outer section)

The S06 sticky-nav fix (decision 40) relies on the outer `<section id="mcentre-nav">`:
- `src/seo/page-shell.ts:378` — `@media (min-width:601px){#mcentre-nav{display:contents}}` dissolves the section's BOX on desktop so `.mnav{position:sticky;top:0}` sticks relative to `.page-col` (the grandparent) instead of the 48px-tall section. Without this, the sticky nav has ZERO sticking range (it scrolls away the instant its 48px section passes the viewport top — a documented S06 defect).
- The element stays in the DOM (the `id="mcentre-nav"` anchor + `getElementById` references intact) — only its box vanishes.

**Therefore the F4 fix CANNOT drop the outer `<section id="mcentre-nav">`** (it would break the desktop sticky nav). The fix must KEEP the outer section + remove its `aria-label` (so it becomes a non-landmark container — a `<section>` without an accessible name is NOT exposed as a landmark per the HTML/ARIA spec). The inner `<nav class="mnav" aria-label="ناوبری بخش‌های صفحه">` becomes the SINGLE landmark. This preserves the sticky-nav architecture + the `id` anchor + the `display:contents` rule, while collapsing the double-landmark to one.

## 2. The WCAG-AA audit (axe-core + WAVE style — the DOM/ARIA check categories)

Every check below names the axe-core rule (the `axe-core` rule ID) or the WAVE check it mirrors, so the owner can cross-reference against a future live axe/WAVE run. The checks are applied to the live production DOM (the Bayern vs Köln match page, 2026-11-15).

### 2.1 Landmarks (axe-core `region` / `landmark-complementary` / `landmark-unique`; WAVE "Heading/Region" checks)

- **F1 + F4: redundant landmarks.** The hero carries TWO `<section>` landmarks (F1) + the nav carries a `<section>` + a `<nav>` landmark with the same label (F4). axe-core's `landmark-unique` would flag both as "landmarks should have a unique role + accessible name" (the hero's two «تیم‌ها و وضعیت بازی» / «خلاصه بازی» regions; the nav's two «ناوبری بخش‌های صفحه» region/navigation). **Finding: 2 redundant-landmark issues (F1 MEDIUM + F4 LOW).**
- **The other 9 sections (summary/standings/form/venue/schedule/faq/related/telegram/footer-hook):** each carries a SINGLE `<section id="mcentre-X" aria-label="<Persian>">` with a UNIQUE Persian label. No redundancy. **PASS.**
- **The main landmark:** `<main id="main">` is present (the skip-link target). axe-core `landmark-one-main` PASS.
- **The header/footer:** `<header id="topbar">` + `<footer>` present. axe-core `landmark-banner` + `landmark-contentinfo` PASS.

### 2.2 Image alt text (axe-core `image-alt`; WAVE "Missing Alt Text")

- **F2: the hero portraits (`mport`) carry `alt=""` (decorative).** The portraits are the ONLY place the featured player identity appears (the adjacent text carries the team names, not the player names). axe-core's `image-alt` PASSES `alt=""` (decorative is a valid alt — axe does not flag empty alt). BUT the WCAG 1.1.1 intent (the image conveys information NOT in adjacent text) is VIOLATED — a screen reader user does not learn the featured player. WAVE's "Missing Alt Text" would not flag it either (alt="" is present), but the WAVE "Alert" category (image with empty alt that may convey information) would surface it for review. **Finding: 2 images (the 2 portraits) where the alt="" is technically valid but the information is not conveyed elsewhere (F2 LOW — a judgment call).**
- **The crests (`mcrest`) + the competition logo (`mcomplogo`):** `alt=""` (decorative). The team/competition NAMES are in the adjacent text (`.mname` / `.mchip`). axe-core `image-alt` PASS. The decorative alt is the CORRECT choice (the crest is visual reinforcement of the adjacent name). **PASS.**
- **All other images** (the chevron SVG in the back-to-top button, the FAQ chevrons, etc.): carry `aria-hidden="true"` + `focusable="false"`. axe-core `svg-img-alt` PASS (decorative SVGs).

### 2.3 Contrast (axe-core `color-contrast`; WAVE "Contrast Errors")

- **The design-system tokens** (re-verified by `check-a11y.js` line 86-107 + the S20 gate): `#0f172a`/`#1e293b` (dark navy bg) + `#f1f5f9`/`#e2e8f0` (light text ≈ 15:1 ratio — ≥4.5:1 AA for normal text) + `#7dd3fc` (icy-blue accent ≈ 11:1 on dark navy — ≥3:1 AA for large text + UI components). - **No contrast failures found.** (The S23 §2.6 + the S20 gate already verified this; S25 re-verifies the tokens are unchanged.)

### 2.4 Focus + keyboard (axe-core `focus-order` / `tabindex` / `focusable-content`; WAVE "Keyboard")

- **The skip-link «پرش به محتوا»** is the FIRST focusable element (Tab 1 — verified live). It is off-canvas until `:focus` (the `.skip-link:focus` CSS reveals it). WCAG 2.4.1 Bypass Blocks. **PASS.**
