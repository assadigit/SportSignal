### The honest verdict (the "documented owner decision" branch)

**The wiring fix is verified and live**: after the deploy,
`priorityHinted:true` + `requestDiscoverable:true` on every run, the
poster's on-wire priority flipped **Medium → High**, its fetch runs from
HTML-byte-0 in parallel with the CSS (load delay 18–19 ms, duration
64–74 ms), and the observed (unthrottled) LCP == FCP at 0.9–1.5 s — the
poster paints at first paint.

**The <2.5 s lab target is NOT met by priority wiring alone**: the lab
LCP is statistically unchanged (medians 6.19 → 6.29 s, both series inside
the documented 5.6–7.1 s variance band). The residual is NOT the image —
it is the render-blocking chain (HTML ≈181 KB + CSS ≈137 KB
parse/apply/first-layout) amplified by the lab's 4× CPU throttle. The
arithmetic is consistent on every run: the simulated FCP→LCP gap
(3.3–4.4 s) tracks ~4× the observed element-render-delay window
(393–1,313 ms), and simulated FCP itself sits at 2.2–2.8 s (network
floor: TTFB + HTML + CSS on slow 4G). This is the same "lab LCP floor"
the web-optimization program documented at its Phase-7 close (K15 NOT
met, median 6.4 s, same attribution).
