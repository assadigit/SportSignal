## The owner's directive

> "Ok now add a TAP, mouse hover tool tip that shows what it means for
> example: رتبه در پریمیرلیگ / رتبه در لیگ قهرمانان"

The S37 badge answered "what position" with a bare number; the number
itself could not say "in WHICH competition". S38 adds the explanation on
demand: a small dark bubble carrying the SAME localized label the badge
already has as its accessible name — «رتبه ۶ در لیگ برتر انگلیس» /
"6th in Premier League" (the owner's requested pattern, with the digit
and the site-standard competition name — DECISIONS 2026-11-09).

## What was built

- **`public-13.75.js -> 13.76.js`** — `rankBadge()` also stamps `data-tip`;
  ONE delegated listener set on `document` (capture-phase click, the
  sharewrap-closer precedent) + ONE shared `#rankTip` bubble in `body`
  cover the SSR badges AND every client re-render with zero per-chip
  wiring (nothing to rebind on lang switch or poll tick):
  - **hover** (hover-capable devices): 200ms rest on the circle, hide on
    leave; `(hover: none)` devices skip the path entirely (the tap-
    emulated mouseover never double-fires);
  - **tap**: instant toggle — the tooltip IS the tap's purpose, so the
    badge `preventDefault()`s the card-link navigation (the card body
    still navigates); outside tap, `Escape`, any scroll/resize and every
    `rerenderAll()` close it;
  - the native `title` strips on first interaction (no double tooltip;
    the no-JS SSR view keeps it); `aria-describedby="rankTip"` links the
    bubble while visible; no `tabindex` — ~60 badges must not flood the
    keyboard tab order (screen-reader a11y stays on `aria-label`);
  - geometry from `getBoundingClientRect`: centered above the chip,
    viewport-clamped (8px margins), flipped below when there is no room
    above, the arrow tracking the chip's center via `--ranktip-ax` —
    pure geometry, RTL and LTR share the one rule.
- **`public-13.82.css -> 13.83.css`** — `.ranktip`: elevated-slate bubble
  in the badge's own ink family (`#0c1728`/`#D6E9FA`), borderless so the
  arrow is seamless, `z-index:70` above the sticky bar,
  `pointer-events:none`, 140ms fade+rise (`prefers-reduced-motion`
  honored), `.up`/`.down` arrow states, light-theme pair
  (`#ffffff`/`#31567c`).
- **`seo/markup.ts`** — the SSR twin `rankChipHtml` carries `data-tip`

## Known notes (documented, deliberate)

- **The transient crest kiss:** on desktop rows the 53px crest tops rise
  ~14.5px above the badge top, so a 10px-gap bubble can overlap the
  crest's transparent-corner airspace by ~4px WHILE VISIBLE
  (`pointer-events:none` — nothing is blocked; the overlay is standard
  tooltip semantics and vanishes on close). If the owner dislikes it, a
  gap bump 10 -> 16px clears every measured crest top — one more rename
  round (13.77.js + 13.84.css + 2 more sweep evictions); noted as a
  next-session candidate, not worth the churn unprompted.
- The arrow is intentionally quiet (5px): the association is carried by
  the centering + the gap; bumping it to 6px rides the same rename round
  if ever wanted.
- The tooltip closes on every poll re-render (`rerenderAll()` — the
  re-rendered list detaches the chip the bubble points at); a
  tap-pinned bubble therefore lives at most one poll cycle (~60s live /
  up to 15min idle).
