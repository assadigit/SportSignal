# S37 — the team competition-rank chip on the match cards (v13.248-rankchip)

**Date:** 2026-11-09 · **Session:** S37 · **Release:** v13.248-rankchip

## What the owner asked for

The uploaded design pack `sportsignal-team-rank-design-pack.zip` (root, now
filed at `docs/assets/`): a small circular indicator containing ONLY the
team's ranking number beside each team's name on the match cards — the
team's position in THE FIXTURE'S OWN competition, both teams independent,
RTL + LTR, graceful omission when no meaningful rank exists, zero new
backend workload, zero redesign of the cards.

## What shipped (verified end-to-end)

1. **The server resolution** (`src/public-matches.ts`): three pure, exported
   functions — `teamRankSets` (builds code → Map<normalizedName, pos> from the
   LIVE tables), `rankApplicable` (the fixture-phase gate: domestic cups and
   the explicit RANK_KO_STAGES set never rank; LEAGUE_PHASE/LEAGUE_STAGE/
   GROUP_STAGE/REGULAR_SEASON do — deliberately NOT faStageName, whose
   STAGE_FA carries the league-phase DISPLAY labels), `attachTeamRanks`
   (stamps `homeTeam.rank`/`awayTeam.rank` on the shaped rows, each side
   independent, omitted when unresolvable). Zero new subrequests: the stMap
   read (cache-only fetchStandings) already existed on every payload build.
   Pre-season `started:false` tables and stale snapshot tables never feed
   badges.
2. **The SSR mirror** (`src/seo/data.ts` + `src/seo/markup.ts`): the SEO
   context reads the same seven `standings_cache_*` KV keys (reads only) and
   `sideHome`/`sideAway` render the badge for list rows + spotitems — the
   no-JS first paint mirrors the client class-for-class.
3. **The client** (`assets/public-13.75.js`, rename-on-edit from 13.74):
   `teamRow()` + `rankBadge()` — render() and spotItemNode() route through
   them. Logical DOM order (home `[badge, name]` / away `[name, badge]` +
   logical justify packing) puts the badge on the name's OUTER flank (crest
   side, away from the central kickoff column) in BOTH RTL and LTR — one
   rule, no direction branches. Digits via fmtNum (Persian in FA); localized
   title + aria-label («رتبه ۳ در لیگ برتر انگلیس» / "3rd in Premier
   League"). NO rank → the plain `.team` markup, byte-identical.
4. **The stylesheet** (`assets/public-13.82.css` from 13.81): `.rankchip`
   (22px true circle, --rank-chip-* tokens, 1px cool-blue border, tabular
   digits; 20px + centered group under 600px; the live card's compact 18px)
   + `.team.team-r`. Nothing else touched.
5. **The plumbing**: reference bumps (public.ts + seo/page-shell.ts),
   `_headers` pins for both new assets (cap sweep #18 evicted the expired
   /public-13.48.css + /public-13.49.css pins — files stay on disk), SW
   cache v121, heroes:sync regen, version 13.248.0.0, CHANGELOG, DECISIONS.
6. **The gate**: NEW `scripts/check-team-ranks.js` (27 checks — resolution,
   name folding, phase gates, one-sided ranks, pre-season/stale exclusion,
   SSR mirror, client bundle, stylesheet) wired into `npm test`; the
   live-read co-evolutions (check-stats js62/css reads + the v13.247→
   HISTORICAL demotion + the v13.248 live wiring check, check-a11y,

## Coverage limitation (documented, deliberate)

EL/ECL league-phase tables are not in the cron stand_refresh set nor in the
public payload's stMap — adding them would mean NEW provider fetches
(against the task's reuse-only constraint). EL/ECL fixtures render without
badges. INTL cups, the Hazfi Cup and knockout rounds likewise carry no
badge (no official table in the pool). See the audit + DECISIONS.
