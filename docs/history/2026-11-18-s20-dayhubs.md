## 3. The budget (the audit's math, held)

- **Subrequests**: FD +4 comps = the SAME single batched call (+0). The intl
  scan: ≤12 calls (4 slugs × 3 dates) and ONLY on window days (the
  emptiness gate); club days +0. The 44-metered stop is the hard backstop.
  The live tick right after deploy measured `subreq_last_tick: 31` — the
  quiet-tick profile unchanged.
- **KV**: reads unchanged (no new keys; the fill adds zero KV reads/writes
  of its own — it rides the sweep's existing pool write). The snapshot of
  the live `kv_writes_day: 433` matches the pre-S20 quiet-day profile.
- **Pool size**: the audit's worst case ~550 rows ≈ 230KB — under the 331KB
  slim norm, far under the 617KB that killed CPU in the v13.111 era. The
  slim whitelist already covers the new rows' fields (id/utcDate/status/
  competition.code/…).
- **CPU**: zero page-builder changes, zero client asset renames (a
  server-side release — the SW cache stays `sportsignal-v126`, `_headers`
  untouched at the 100-rule cap, no new pins needed).
