## 3) The elision incident — caught LIVE, fixed twice, gated forever

**The bug**: the bundle-builder appended its separator AFTER the
HERO_ART block's trailing comment (Tottenham's entry ends
`…kit VLM-verified */`, its comma BEFORE the comment) — an
object-literal **elision = SyntaxError**. `public-13.72.js` loaded
(HTTP 200) but executed NOTHING: no carousel, no countdown, no client
render. SSR content still painted, healthz stayed `ok:true`, and every
offline gate was green (regex extraction, parity baseline, the wrangler
healthz/homepage smoke — the 2026-09-15 lesson class exactly: regex
cannot see runtime-only failure). **The post-deploy live browser check
caught it** (`heroArtFor` undefined, lanes empty) — the tool class the
RUNBOOK's own history mandates.

**Fix 1** (fd2ffec, ~10 min later): the one comma removed + **the
syntax gate** added to npm test (`new Function()` compiles the live
bundle + the pinned-era read as real JavaScript — a parse failure now
fails the suite) + the comma rule fixed in both generators (decide the
separator on the comment-stripped tail, never two).

**Fix 2 — the ADR-006 rename** (d8f58bc): fix 1 had edited the
immutable-published `13.72.js` in place — stranding any client that
fetched the broken bytes in the window (immutable = never revalidated,
for a year). The rule-following cure: **public-13.72.js → 13.73.js**
(SW v115 → v116; 13.72.js stays served one SEO TTL carrying the FIXED
